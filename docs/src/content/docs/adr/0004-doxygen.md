---
title: 'ADR 4: Doxygen for the Java reference'
description: Why the Java reference is generated by Doxygen and gated in CI.
---

**Status:** superseded by [ADR 6](../0006-javadoc/) in 2.9.2

## Context

The documentation site links a browsable Java reference, and CI should fail when public code is left undocumented.

## Decision

Doxygen generates the reference (`scripts/docs.sh`) and `--strict` fails on any warning. It reads `README.md` as its
main page, renders source browsing, and documents only public, protected and package members (private members are not
extracted, so they need no comments). A small Perl filter teaches it records and annotation defaults.

## Consequences

- One tool produces the HTML for the site and the documentation gate.
- CI installs a pinned Doxygen binary, and the Perl filter must keep up with Java syntax Doxygen does not parse.
- `maven-javadoc-plugin` with `-Xdoclint` is the alternative if the filter ever becomes a burden.
